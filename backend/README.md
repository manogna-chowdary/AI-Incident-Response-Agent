# Backend

FastAPI service for the AI Incident Response Agent.

## Setup

Create the virtual environment and install dependencies:

```bash
cd backend
python -m venv .venv
```

Activate it (PowerShell):

```powershell
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Database

Configuration comes from `DATABASE_URL` in `backend/.env`:

```
DATABASE_URL=postgresql+asyncpg://postgres:YOUR_PASSWORD@localhost:5432/incident_response
```

Apply migrations:

```bash
alembic upgrade head
```

Check the current revision, or preview the SQL without changing anything:

```bash
alembic current
alembic upgrade head --sql
```

## Run

```bash
uvicorn app.main:app --reload
```

The server starts on http://localhost:8000, with interactive docs at /docs.

## Endpoints

| Method | Path | Does |
| --- | --- | --- |
| GET | `/health` | Liveness check |
| POST | `/incidents` | Create an incident (201) |
| GET | `/incidents` | List all incidents, newest first |
| GET | `/incidents/{incident_id}` | Fetch one incident, 404 if unknown |

`incident_id` is generated by the server as `INC-<YYYYMMDD>-<6 hex chars>`.
`status` defaults to `open`. `root_cause`, `resolution`, and `outcome` start
null and are filled in as the incident progresses.

```bash
curl -X POST http://localhost:8000/incidents `
  -H "Content-Type: application/json" `
  -d '{"service":"payments-api","description":"Elevated 5xx","severity":"high"}'
```

## Current scope

Incidents are stored and served as plain CRUD. No AI agent logic, no memory
layer, and no authentication yet.

| Path | Purpose |
| --- | --- |
| `app/main.py` | App instance, mounts the router, `/health` |
| `app/routes.py` | The three incident endpoints |
| `app/schemas.py` | Pydantic request and response models |
| `app/models.py` | `Incident` table plus severity and status enums |
| `app/db.py` | Engine, session factory, `Base` |
| `app/config.py` | Settings loaded from the environment |
| `alembic/` | Migration environment and versions |
